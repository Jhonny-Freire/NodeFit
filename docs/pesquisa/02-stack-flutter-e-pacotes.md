# stack-2026: framework choice, IDE, package versions, Health Connect, Android/Windows toolchain, and on-device AI for a solo-dev offline-first gym notebook app (Galaxy S26 first, later iOS/desktop). Checked on 2026-10-14.

## 1. Which framework should this case use: Flutter, KMP + Compose Multiplatform, native Kotlin + Jetpack Compose, or React Native/Expo?
[likely]
VERDICT: use Flutter (Dart). It fits this case best because: (a) it is already installed (Flutter 3.47.1 / Dart 3.13.1); (b) one codebase and one UI cover Android, iOS, Windows, macOS and Linux, and Flutter desktop has been stable since 2022 (Windows with Flutter 2.10 in Feb 2022, macOS/Linux with Flutter 3 in May 2022); (c) the core value is an offline-first relational notebook (workouts, sets, machine settings, notes, measurements), and Drift covers that on every platform with one schema; (d) there are mature plugins for charts (fl_chart 1.2.0), photos (image_picker on all 6 platforms), notifications (flutter_local_notifications on all 6) and Health Connect/HealthKit (health 13.3.2). Known gaps to plan for: the `health` plugin is Android/iOS only, and its writeWorkoutData has no exercise segments, sets or reps, so the app's own database must stay the source of truth. Gemini Nano is reachable only through community plugins. The `camera` plugin is Android/iOS/web only (no desktop). WHEN THE OTHERS WIN: (1) Native Kotlin + Jetpack Compose (Compose BOM 2026.09.00, Room 2.8.5, Vico, Health Connect connect-client 1.1.0 stable / 1.2.0-alpha06) is better if the app will stay Android-only, or if he wants first-class Health Connect features (exercise segments with repetitions, PHR) and Google's official on-device AI path (ML Kit GenAI + Firebase AI Logic hybrid, which is native Android only and experimental). It is also better if he wants Kotlin/Android job-market skills. (2) KMP + Compose Multiplatform is better if he prefers Kotlin and wants shared logic with an Android-native feel, plus the option of SwiftUI on iOS later. The trade-off: Health Connect, HealthKit, camera and notifications need expect/actual code per platform, desktop runs on the JVM (larger installers), and the plugin ecosystem is smaller than Flutter's. (3) React Native/Expo (RN 0.87.1, Expo SDK 57) is better only if he already knows React/TypeScript, or wants Expo EAS cloud builds to produce iOS binaries without owning a Mac. Its desktop story is weaker: react-native-windows 0.84.0 and react-native-macos 0.83.0 lag core RN 0.87. Every option needs macOS + Xcode (or a cloud macOS builder) to build and sign iOS.

## 6. Is Riverpod 3 stable, and is code generation still recommended?
[verified]
Yes, Riverpod 3 is stable. flutter_riverpod 3.0.0 was published 2025-09-10 and 3.4.3 is current. Key 3.0 changes: a single unified Ref type with Ref.mounted; AutoDisposeNotifier and FamilyNotifier merged into Notifier; automatic retry with exponential backoff (200 ms up to 6.4 s by default); provider errors wrapped in ProviderException; StateProvider, StateNotifierProvider and ChangeNotifierProvider moved to `package:riverpod/legacy.dart` and discouraged. Offline persistence and Mutations are EXPERIMENTAL. Codegen is optional. Riverpod's docs say they recommend it, but if you do not already run codegen (Freezed or json_serializable), it is 'probably not worth it' just for Riverpod. Some features need it: generic providers and the statically safe scoping lint. Practical implication: Drift already requires build_runner, so adding riverpod_generator costs little.

## 7. Are Dart macros stable, and what codegen changes affect freezed/riverpod_generator?
[verified]
No. Dart macros were cancelled: the Dart team 'indefinitely paused' them in January 2025 (blog post 'An update on Dart macros & data serialization', 29 Jan 2025), and the experimental macros docs were removed. What shipped instead: (1) Primary constructors are a stable language feature in Dart 3.13.0 (released 2026-08-12), enabled with `sdk: ^3.13.0`, e.g. `class Point(var int x, var int y);` plus `new(...)`/`factory` body syntax. Breaking change: `final`/`var` are no longer allowed on non-declaring parameters. The freezed README now says that with Dart 3.13 you no longer need freezed for primary constructors, but it still generates ==, toString and copyWith via build_runner. (2) Analyzer plugins (Dart 3.10+): riverpod_lint moved from custom_lint to analysis_server_plugin. (3) build_runner 2.16 now always fixes edited generated files, and adds `--only-check` and `--keep-modified-outputs`. (4) Build hooks / native assets are stable enough that sqlite3 3.x bundles SQLite through them. build_runner is still required for drift_dev, freezed, json_serializable and riverpod_generator.

## 8. Drift vs sqflite vs Isar for an offline-first app that must later run on Windows/macOS/Linux/web; is sqlite3_flutter_libs still needed?
[verified]
Use Drift. Drift 2.35.2 runs on Android, iOS, macOS, Windows, Linux (NativeDatabase) and web (WasmDatabase, which needs a worker setup). Since drift 2.32.0 (2026-02-28) it uses sqlite3 3.x (3.0.0 released 2025-11-13), which bundles a recent SQLite automatically through Dart build hooks, so desktop needs no extra setup. Drift's docs say it is 'no longer necessary to depend on sqlite3_flutter_libs or sqlcipher_flutter_libs'. Both are now empty '+eol' packages (0.6.0+eol / 0.7.0+eol), so remove them. drift_flutter 0.3.1 still references them transitively, which is harmless. SQLCipher/SQLite3MultipleCiphers encryption is configured through sqlite3 hook options. Drift also adds typed queries, migrations, streams and codegen. sqflite 2.4.4+2 supports only Android, iOS and macOS. Windows/Linux need sqflite_common_ffi 2.4.4, and web needs a separate ffi_web package. That is a weak point of the Gemini plan. Isar: the original `isar` package's last stable is 3.1.0+1 (2023-04-25), with pubspec sdk <3.0.0, plus 4.0.0-dev.14 (2023-08-21); its GitHub repo was last pushed 2025-06-14, so it is effectively unmaintained. The community fork isar_community 3.4.1 (2026-10-13) is active, but its tags show no web support. Do not choose Isar for a new project.

## 11. Does Samsung Health sync weight, body fat, steps, exercise sessions and nutrition to Health Connect?
[verified]
Yes. ## 12. Which Flutter package supports Health Connect, and what does it require?
[verified]

## 14. What is the standard fix for flutter doctor's 'cmdline-tools component is missing' and 'Android license status unknown'?
[verified]
Open Android Studio > More Actions (or Tools) > SDK Manager. On SDK Platforms, check the first API Level 36 entry. On SDK Tools, check Android SDK Build-Tools, Android SDK Command-line Tools (latest), Android Emulator, Android SDK Platform-Tools, CMake and NDK (Side by side). Click Apply. Then run `flutter doctor --android-licenses` and accept each license until 'All SDK package licenses accepted.' appears, then re-run `flutter doctor`. Cause: flutter_tools checks for the `cmdline-tools` directory (sdkmanager), and without it license status cannot be determined. The local SDK already has a `licenses` folder, but there is no cmdline-tools. For the physical Galaxy S26: enable Developer options and USB debugging, and install the Samsung OEM USB driver on Windows (wireless debugging is optional).

## 16. What does flutter_local_notifications need on Android (rest timer and reminders)?
[verified]
Version 22.3.2 needs core library desugaring (isCoreLibraryDesugaringEnabled = true plus com.android.tools:desugar_jdk_libs:2.1.4, even without scheduled notifications), Java 17 source/target/jvmTarget, multiDex, AGP >= 8.11.1 and compileSdk 35+ (examples use 36). The plugin declares POST_NOTIFICATIONS (call requestNotificationsPermission() on Android 13+) and VIBRATE. Scheduled notifications need RECEIVE_BOOT_COMPLETED plus receivers, and either SCHEDULE_EXACT_ALARM (the user grants it) or USE_EXACT_ALARM (no prompt, but subject to store approval). Samsung reportedly caps scheduled alarms at 500. Supported platforms: Android, iOS, macOS, Linux, Windows, web.

## 17. Is Gemini Nano available on the Galaxy S26 via AICore / ML Kit GenAI Prompt API, and is there a Flutter plugin?
[verified]
Yes, in beta. Google's ML Kit GenAI page lists the Prompt API on Galaxy S26/S26+/S26 Ultra with Gemini Nano 'nano-v3'. Z Flip8/Fold8/Fold8 Ultra run nano-v4, and Z Fold7/TriFold run nano-v2. The Galaxy S25 is not listed for the Prompt API, only for Summarization, Proofreading, Rewriting and Image Description. Status: the Prompt API is Beta (no SLA, breaking changes possible), with structured output in Alpha. The dependency is com.google.mlkit:genai-prompt:1.0.0-beta4 and it needs API 26+. It accepts text or image+text (multiple images allowed). Input must be under 4000 tokens. Inference runs only while the app is the top foreground app (BACKGROUND_USE_BLOCKED otherwise), with per-app and battery quotas (BUSY, PER_APP_BATTERY_USE_QUOTA_EXCEEDED). It is not supported on unlocked bootloaders. You must call checkStatus() and download() first. Flutter: google_mlkit_genai_prompt 0.3.1 (2026-08-17, flutter-ml.dev, MIT, NOT a Google package, Android only, minSdk 26, supports text plus imageData). Alternatives: gemini_nano_android 1.2.1, flutter_local_ai 0.2.1 (Gemini Nano, Apple Foundation Models, Windows AI Foundry, Chrome) and flutter_edge_ai 2.3.3, which runs Gemma/LLMs on all platforms and replaces the discontinued flutter_gemma. Cloud option without an embedded key: Firebase AI Logic (firebase_ai 4.0.0 for Flutter) keeps the Gemini key server-side, protected by App Check and per-user rate limits. Its hybrid on-device/cloud mode (firebase-ai-ondevice 16.0.0-beta01, announced 2026-04-17) is experimental and documented for native Android only, so I found no Flutter hybrid support. The Prompt API takes text and images, not PDFs, so diet/workout PDFs must be text-extracted or rendered to images and chunked to fit the 4K-token limit.

## IMPLICATIONS
- Go with Flutter. Upgrade first: `flutter upgrade` moves 3.47.1 to 3.47.7 (Dart 3.13.5) on the same stable line. Do not switch to the beta (3.49 pre).
- Fix the toolchain before coding. In SDK Manager > SDK Tools install Android SDK Command-line Tools (latest), CMake and NDK (Side by side), and on SDK Platforms install API 36 (only 36.1 is present now). Then run `flutter doctor --android-licenses`. The bundled JBR 21.0.10 already meets Java 17+, so do not install a separate JDK. Windows desktop can wait: install Visual Studio Community (or Build Tools) with 'Desktop development with C++' only when he starts the PC version.
- Editor: use VS Code, where the Dart/Flutter extensions are already installed, or install the Flutter plugin 97.0.0 in Android Studio. Keep Android Studio anyway for SDK Manager, the emulator and Logcat.
- Keep Flutter's Android defaults (compileSdk/targetSdk 36, AGP 9.1.0, Gradle 9.3.1, KGP 2.4.0). Raise minSdk to 26 in android/app/build.gradle.kts because `health` and ML Kit GenAI need it. targetSdk 36 already meets the Google Play rule that applies since 2026-08-31.
- Database: replace the Gemini plan's sqflite with Drift 2.35.x + drift_flutter + drift_dev + build_runner. Do not add sqlite3_flutter_libs (it is now an empty EOL package). This gives one schema for Android, iOS, Windows, macOS and web, plus migrations, reactive streams and optional SQLCipher. Avoid Isar.
- State and models: Riverpod 3 (flutter_riverpod 3.4.3). Since build_runner is already there for Drift, riverpod_generator 4.0.9 + riverpod_annotation 4.0.7 cost little. Add riverpod_lint 3.1.9 under `plugins:` in analysis_options.yaml, not via custom_lint. Use Dart 3.13 primary constructors for simple value classes, and Freezed 4.0.2 only where copyWith/unions really help. Do not use legacy StateNotifier/StateProvider, and avoid Riverpod's experimental offline persistence and Mutations for the core data path.
- Routing and UI: go_router 18.0.2 is fine but frozen at feature-complete. Decide early whether to start on `package:material_ui` (Flutter 3.47 opt-in; the in-SDK Material is frozen and scheduled for deprecation). If he does, check that third-party widgets like fl_chart work with the MaterialUiCompatibilityBridge.
- Health Connect: use the app's own Drift database as the source of truth for sets, reps, RIR, notes and machine settings (seat height, backrest, pin). Health Connect cannot hold that, and the health plugin writes only session summaries. READ weight, body fat, height and steps from Health Connect, which Samsung Health syncs, so a smart scale or Galaxy Watch feeds the weekly evolution charts. WRITE a summary ExerciseSession (STRENGTH_TRAINING) and optionally NutritionRecord. Request READ_HEALTH_DATA_HISTORY to import more than 30 days back. Implement the privacy-policy rationale activity and FlutterFragmentActivity. Samsung Health syncs only when its app is opened, so show a 'last synced' date.
- Photos: use image_picker 1.2.4 for meal and progress photos (system camera/gallery, all platforms). Skip the `camera` plugin unless a custom viewfinder is needed, because it has no desktop support.
- Arena/workout mode: wakelock_plus 1.8.1 keeps the screen on. flutter_local_notifications 22.3.2 handles rest-timer alerts; it needs desugaring and POST_NOTIFICATIONS, and exact alarms only if truly needed (Play policy).
- AI import: drop the Gemini plan's embedded API key. Phase 1: manual entry and templates, no AI. Phase 2, optional: on-device Gemini Nano on the S26 via google_mlkit_genai_prompt (beta, community plugin, Android only, foreground only, under 4K tokens, PDFs must first be converted to text or images). Gate it with checkStatus() and keep a manual fallback. Alternatively, a cloud call through Firebase AI Logic with App Check, which keeps the key off the device.
- Plan for iOS: any framework needs a Mac with Xcode, or a cloud macOS CI such as Codemagic or GitHub Actions macOS runners, to build and sign iOS. The health plugin covers HealthKit (iOS 15+) with the same Dart API, and Gemini Nano features will not exist on iOS.
- Revisit native Kotlin/Compose only if he decides the app will be Android-only forever, or needs Health Connect exercise segments with reps, or Firebase hybrid on-device AI, which are native-first. Revisit KMP + Compose Multiplatform only if he strongly prefers Kotlin.
